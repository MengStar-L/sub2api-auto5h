可配置安装与完全卸载

让 sub2api-auto5h 的程序、配置、数据和备份集中在用户选择的安装根目录，同时保留 systemd 权限隔离、可升级性和安全的完整清理。

默认根目录/opt/sub2apiauto5h
默认监听127.0.0.1:2555
输入方式TTY 交互或环境变量

目标与边界

  • 新安装允许选择安装根目录和监听端口；直接回车或无 TTY 时使用默认值。
  • 二进制、环境文件、SQLite、WAL/SHM 和升级备份均位于同一个安装根目录。
  • systemd unit 必须位于系统 unit 目录；专用系统用户和组属于系统级资源。这是单目录目标仅有的外部资源。
  • 监听主机固定为 127.0.0.1，此变更不引入公网 HTTP 绑定选项。
  • 提供可独立下载且随 Release 打包的完全卸载脚本。

目录布局与权限

路径所有者/权限用途
<root>/sub2api-auto5hroot:root，0755服务二进制
<root>/uninstall.shroot:root，0755与当前布局匹配的卸载器
<root>/config/sub2api-auto5h.envroot:sub2api-auto5h，0600主密钥、监听地址、数据库路径与 Cookie 设置
<root>/data/sub2api-auto5h:sub2api-auto5h，0700SQLite、WAL 和 SHM
<root>/backups/sub2api-auto5h:sub2api-auto5h，0700升级前数据库归档
/etc/systemd/system/sub2api-auto5h.serviceroot:root，0644根据实际根目录生成的 systemd unit

unit 的 ExecStart、EnvironmentFile 与 ReadWritePaths 均使用已经验证的绝对安装路径。ProtectSystem=strict 保持启用，只允许服务写入 data 和 backups。

安装输入与校验

交互模式

当 /dev/tty 可读写且对应环境变量未设置时，安装器从 TTY 询问安装目录和端口，因此通过 curl | sudo sh 启动时仍可交互。每项直接回车采用默认值。

非交互模式

curl -fsSL https://raw.githubusercontent.com/MengStar-L/sub2api-auto5h/main/scripts/install.sh |
  sudo SUB2API_AUTO5H_INSTALL_DIR=/srv/sub2apiauto5h \
       SUB2API_AUTO5H_PORT=3000 sh

SUB2API_AUTO5H_INSTALL_DIR 和 SUB2API_AUTO5H_PORT 的存在会跳过对应提示。无 TTY 且未设置变量时使用 /opt/sub2apiauto5h 与 2555。

端口只接受十进制 1–65535。安装目录必须可规范化为安全的绝对路径；拒绝空值、控制字符、.. 路径段、文件系统根以及 /opt、/usr、/etc、/var、/bin、/sbin 等宽泛系统目录。

安装与升级流程

  1. 验证 root 权限、架构、安装参数及必需命令，再下载指定或最新 Release。
  2. 验证 SHA256SUMS 后解包；任何失败均不修改现有服务。
  3. 停止既有服务，确定当前布局，并在替换前备份数据库及 WAL/SHM。
  4. 创建根目录及子目录，原子替换二进制和卸载器，生成使用实际路径的 unit。
  5. 首次安装生成主密钥和环境文件；原地升级保留环境文件、主密钥和数据库。
  6. 执行 systemctl daemon-reload，启用并启动服务；打印实际目录、面板地址和 setup token 查询命令。

v0.1.0 旧布局迁移

若发现旧 unit 使用 /usr/local/bin/sub2api-auto5h，并且目标根目录尚无配置或数据，安装器会把 /etc/sub2api-auto5h/sub2api-auto5h.env 和 /var/lib/sub2api-auto5h 中的数据库文件安全迁移到新布局，保留原主密钥，并重写监听地址与数据库路径。迁移成功、服务启动后才清理旧项目专属路径；迁移前先生成备份。

如果目标目录已有不同配置或数据库，安装器必须停止并报告冲突，不可静默覆盖或合并两个实例。

完全卸载流程

卸载器优先使用 SUB2API_AUTO5H_INSTALL_DIR，否则从已安装的 unit 中读取带明确标记的根目录。解析后的路径必须再次通过与安装器相同的安全校验。

  1. 展示将删除的 systemd unit、精确安装根目录、数据库、配置、备份和专用账号。
  2. 默认要求输入完整确认词；自动化时仅接受 SUB2API_AUTO5H_UNINSTALL_CONFIRM=yes。
  3. 停止并禁用服务，删除 unit，执行 daemon-reload 和 reset-failed。
  4. 只对已解析、已验证且精确匹配的安装根目录执行递归删除。
  5. 删除项目专用的旧版二进制、配置和状态目录（存在时），再删除专用用户与组。

完全卸载不可恢复，包含 SQLite、主密钥和所有本地备份。脚本不会保留数据库，也不会删除安装根目录之外的任意用户文件。

代码、文档与发布变更

  • scripts/install.sh：参数输入、路径/端口校验、动态 unit、单目录布局、旧版迁移和升级备份。
  • scripts/uninstall.sh：交互确认、安装位置发现、安全删除和账号清理。
  • packaging/sub2api-auto5h.service 与 env 示例：改为默认根目录和端口。
  • internal/config：无环境变量时的监听和数据库默认值与新布局一致。
  • README.md：交互/非交互安装、自定义路径/端口、升级迁移、完整卸载及新 SSH 隧道示例。
  • Release 归档加入 uninstall.sh；CI 对所有 shell 脚本执行 POSIX shell 语法检查。

验收标准

  • 无输入安装落在 /opt/sub2apiauto5h，服务监听 127.0.0.1:2555。
  • TTY 输入与两个环境变量都能覆盖默认值；非法路径和端口在下载或删除前失败。
  • 生成的 unit 只引用实际安装根目录，服务仅能写入该根目录的 data/backups。
  • 原地升级保留主密钥和数据库；v0.1.0 旧布局迁移后无需重新 setup。
  • 卸载未确认时不改变系统；确认后 unit、根目录、配置、数据库、备份和专用用户/组均不存在。
  • GitHub Actions 的 Go、Vue、race、Playwright、amd64/arm64 发布及 shell 语法检查全部通过。
