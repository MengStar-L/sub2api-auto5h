官方 Codex 直连唤醒

让 auto5h 在额度空闲时按需取得单账号 OAuth 凭据，沿用账号代理直接调用 ChatGPT Codex Responses，真实发送糖果题、保存回答，并把额度核验收敛到明确终态。

凭据策略单账号按需导出，仅在内存使用，不写 SQLite 或日志
请求成功HTTP 2xx 且 SSE 出现 response.completed 或等价成功终态
额度成功优先使用直连响应头，缺失时最多补充核验 60 秒

问题与根因

sub2api v0.1.183 与当前主线的 OpenAI OAuth 账号测试接口虽然接收 prompt，但 createOpenAITestPayload 仍把上游输入硬编码为 hi。因此 v0.1.5 声称发送的糖果题没有到达 ChatGPT，上版智商判定没有有效输入基础。

同一测试实现只转发 response.output_text.delta。如果正文仅存在于完成事件中，sub2api 会丢弃正文但仍发出 test_complete + success=true，导致 auto5h 保存空回复并错误标记“智商不正常”。

auto5h v0.1.5 的后置核验在 10、30、60 秒均未看到正用量时直接退出，没有写入终态；账号会一直显示“已请求待验证”。

旧版所有智商结果都必须视为无效；仅修复标签无法让题目真正发送，也无法恢复被 sub2api 丢弃的正文。

数据流与组件边界

1. 调度预检
继续读取 sub2api quota；只有 OpenAI OAuth 母账号、策略已启用、5h 空闲且 7d 可用才进入租约。
2. 临时认证材料
按远端 ID 调用单账号导出，核对身份，必要时由 sub2api 刷新 token，再重新导出一次。
3. 官方直连
按账号代理请求 ChatGPT Codex Responses，发送固定题目，解析 SSE 与额度响应头。
4. 双结果落库
分别保存请求终态、额度核验状态和回答判定；绝不保存 token、代理密码或原始 SSE。

CredentialProvider

  • 调用 GET /api/v1/admin/accounts/data?ids=<id>&include_proxies=true；响应必须恰好包含一个账号。
  • 账号必须为预期的 platform=openai、type=oauth，并通过远端 ID 对应的本地身份哈希、邮箱或 ChatGPT 身份字段核对。导出响应不包含账号 ID，因此必须坚持单 ID、单结果，禁止批量位置映射。
  • 只提取本次调用必需的 access token、过期时间、ChatGPT account ID、可选自定义 User-Agent 和账号代理。refresh token 不由 auto5h 使用。
  • token 临近过期，或第一次官方请求明确返回 401 时，调用 POST /api/v1/admin/openai/accounts/:id/refresh，随后重新导出；每次任务最多刷新一次。

OfficialCodexClient

  • 固定目标为 https://chatgpt.com/backend-api/codex/responses，拒绝重定向，不允许用户配置任意上游 URL。
  • 请求使用 Bearer access token、ChatGPT account ID、配对的官方 Codex User-Agent/Originator、OpenAI-Beta: responses=experimental、store=false 和流式响应。
  • 模型沿用全局或账号覆盖配置；不新增推理强度设置。请求只携带固定题目及“只能返回一个阿拉伯数字”的指令。
  • 解析 response.output_text.delta、response.output_text.done、完成响应中的 output 文本，以及 response.completed/response.done。正文最多保存 2000 个 Unicode 字符，原始 SSE 上限 1 MiB。

额度证据与状态收口

官方响应头的 primary/secondary 顺序不固定。解析器按 *-window-minutes 识别：300 分钟为 5h，10080 分钟为 7d，并读取同组 used-percent 与 reset-after-seconds。

状态含义下一动作
dispatching租约已持有，正在导出凭据或请求官方服务。等待本次尝试结束。
verifyingSSE 已明确完成，但官方响应头没有有效 5h 窗口。在 10、30、60 秒用 sub2api quota 补充核验。
verified官方响应头或后置 quota 已确认 5h 窗口。按确认的 reset + 延迟调度。
accepted_unverified请求明确成功，但 60 秒内没有额度证据。按请求完成时间 + 5h + 延迟保守调度，到期仍预检；这是终态。
retry_wait请求结果不确定，且协调未发现额度前移。按有限退避重试。
attention凭据、代理、身份、权限或响应结构存在不可自动处理错误。停止自动发送，等待管理员处理。

verifying 最长存在 60 秒。验证协程不论成功、失败、错误还是重启恢复，都必须写入 verified、accepted_unverified 或具体错误状态，禁止静默退出。

代理与网络策略

  • 账号绑定代理时，按需导出并严格复用；支持 http、https、socks5、socks5h。
  • 账号未绑定代理时，允许从 auto5h 宿主机直连。
  • 代理导出、解析、DNS、认证或连接失败时进入错误状态，绝不回退宿主机直连，避免出口 IP 关联风险。
  • 第一版不复制 sub2api 的备用代理故障转移状态机；主代理失败时明确报告。
  • HTTP 客户端限制连接、响应头、总请求与 SSE 读取时间；TLS 校验不可关闭。

错误与重试

信号处理
401让 sub2api 刷新一次、重新导出并重试一次；再次 401 进入 attention。
429解析 5h/7d 响应头并等待相应 reset；缺少可信窗口结构则进入 attention，不盲重试。
403、404、坏导出、身份不符、未知 SSE作为不可自动恢复错误，禁止 fail-open。
连接中断或超时先查 quota；出现可信 5h 窗口即推断成功，否则沿用 30/60/120 秒有限重试。
明确成功终态无论回答或后置 quota 如何，本周期不再投递。

安全与同意

  • 设置页新增全局“启用直连唤醒”开关和风险确认；新装与升级默认关闭。关闭时调度器只能读取 quota，不能调用凭据导出或刷新接口。
  • SQLite 不增加 access token、refresh token、ID token 或代理凭据字段。审计事件只保存阶段、状态码、脱敏错误、回答和额度证据来源。
  • 所有错误在落库和输出前清除 Bearer token、JWT、refresh token、代理 URL userinfo 和疑似密钥值；HTTP 响应正文只保存经过白名单提取的安全字段。
  • Go 字符串不能保证物理内存清零，因此安全承诺限定为不持久化、缩短对象生命周期、不写日志和不跨任务缓存，不宣称可靠零化。
  • 进程级并发租约继续保证同一账号只有一个直连任务；凭据导出结果不可在账号之间共享。

数据库与迁移

  • 尝试记录增加传输路径、回答来源、额度证据来源和安全终态摘要；摘要不包含原始 SSE。
  • 账号最新回答支持 normal、abnormal、no_answer、legacy_invalid。
  • 迁移把 v0.1.5 的全部回答状态改为 legacy_invalid，保留回答文本与时间并注明题目未被透传。
  • 迁移把超过 60 秒的 success_unverified 改为 accepted_unverified；不因迁移创建新请求。
  • 身份代次变化继续清空最新窗口与最新回答状态，要求管理员重新启用该账号。

面板行为

  • 设置页显示直连总开关、风险确认、凭据不落盘说明和当前可用性。
  • 账号表智商列同时显示状态与回答摘要，例如“智商不正常 · 返回 29”；空回答和旧版无效使用独立标签。
  • 账号抽屉展示完整回答、请求模型、回答时间、传输路径、额度证据来源和安全终态摘要。
  • verifying 显示最长 60 秒倒计时；accepted_unverified 显示“请求成功·额度未确认”，不使用“待验证”措辞。
  • 事件页记录凭据获取成功/失败、token 刷新、代理路径、官方请求、响应头验证和 quota 补充验证，不显示任何秘密。

测试与验收

  • 假 sub2api 覆盖单 ID 导出、零/多账号拒绝、身份错配、token 临期刷新、refresh 失败及敏感信息不落库。
  • 假官方上游覆盖四类代理、无代理直连、代理失败不回退、401 刷新、429 窗口、403/404、超时和连接中断。
  • SSE 覆盖分片 delta、done 正文、completed output 回退、错误终态、空正文、超限正文、坏 JSON 和无完成终态。
  • 额度响应头覆盖 primary/secondary 对调、300/10080 分钟识别、缺失、重复、坏类型和未知窗口。
  • 状态机覆盖立即 verified、60 秒收口、重启恢复、明确成功不重发、并发租约和禁用直连时零凭据调用。
  • 前端 Vitest/Playwright 覆盖风险确认、回答摘要、完整详情、旧版迁移状态、桌面 1440×900 与移动 390×844。
  • 公开 CI 不使用真实 OAuth 凭据；本机不编译。GitHub Actions 完成类型检查、Vitest、Go fmt/vet/unit/race、生产二进制 Playwright、Linux amd64/arm64 交叉编译。

健康路径验收：额度空闲后只导出目标账号一次，使用同一账号代理发送真实糖果题；收到明确完成和有效 5h 响应头后立即进入 verified，保存回答；非 21 或空回答均不重发；缺少额度头时 60 秒内进入明确终态。

发布与升级

实现完成并通过主分支云端检查后发布 v0.1.6。安装脚本与 systemd 布局不变，数据库自动迁移。升级后直连总开关保持关闭，管理员需在设置页阅读风险说明并显式开启；此前启用的账号不会在未确认前读取凭据。
