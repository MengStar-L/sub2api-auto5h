sub2api-auto5h

连接一个 sub2api 实例，在 Plus、Team、Business 账号的 5 小时窗口重置后，定向发送一次最小文本请求以启动新窗口。

独立 sidecar不修改 sub2api，也不访问其数据库
单二进制Go API、调度器、SQLite 与 Vue UI 一体交付
Linux 发布systemd 管理，GitHub Actions 构建 amd64/arm64

边界

  • 仅同步 OpenAI OAuth 母账号；账号自动化默认关闭。
  • 只有 Plus、Team 与 Business 系列套餐可启用；Pro、Free、Enterprise、未知套餐和影子账号均排除。
  • 检测只调用 sub2api 的只读 quota API，绝不调用主动 usage probe。
  • 激活只调用指定账号的 admin test API，请求固定为文本 hi 与 mode=default。
  • v1 只支持单管理员、单 sub2api 连接、单进程，容量目标为 100 个启用账号。

额度判定与状态机

解析器按 limit_window_seconds=18000 识别 5h、按 604800 识别 7d，不依赖 primary/secondary 顺序。缺失整个 rate_limit、字段错型、重复或未知窗口均 fail closed；结构有效且不存在 5h 窗口才属于可启动的已知空状态。

  1. 启用时读取 quota：有未来 5h 窗口则等待 reset 加 grace；7d 耗尽则等待 7d reset；5h 空或过期则创建 bootstrap 周期。
  2. 到期时再次读取 quota。若 reset 已前移，判定外部流量已启动窗口并跳过；否则事务标记 dispatching 后调用 test。
  3. 只接受 SSE test_complete 且 success=true。明确成功后只验证 quota，不再次发送。
  4. 失败或不确定时先协调 quota，再按指数退避重试；重启先协调未决周期，唯一周期键与租约阻止并发重复。

网络 API 不提供幂等键。因此本系统保证“每周期只接受一个成功结果”，但采用成功优先的至少一次投递；超时且 quota 同时不可用时可能发送多个 hi，所有尝试均记录审计。

安全与运维

  • 首次 setup token 为一次性随机值；管理员密码使用 Argon2id，会话仅保存令牌哈希并带 CSRF、Origin、双 TTL 与登录限流。
  • sub2api key 使用环境主密钥派生的 AES-256-GCM 加密，浏览器和日志永不回显；错误主密钥使服务进入未就绪且停止调度。
  • 默认只监听 127.0.0.1:8090；公开访问必须放在 HTTPS 反向代理后。HTTP 仅允许回环/私网并要求显式确认。
  • systemd 使用专用用户、0600 环境文件、StateDirectory、网络与时间同步依赖、沙箱加固和优雅终止。

验收

  • 健康路径在 reset + 30 秒 + 网络耗时内收到一个成功 test；外部已激活时收到零个。
  • 明确 SSE 成功后不重发，重启或并发调度不产生额外周期。
  • 不合格、影子、停用、认证或结构异常账号永不发送激活请求。
  • GitHub Actions 完成后端、前端和浏览器测试，并发布可校验的 Linux amd64/arm64 归档。
