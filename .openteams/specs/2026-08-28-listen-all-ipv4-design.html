默认监听所有 IPv4 接口

移除回环地址限制，让宿主机上的 Docker 反向代理和其他受控网络直接访问管理面板后端。

默认地址0.0.0.0:2555
端口选择0.0.0.0:<所选端口>
协议范围IPv4，不新增 IPv6 默认监听

行为

  • Go 在未设置 SUB2API_AUTO5H_LISTEN 时使用 0.0.0.0:2555。
  • 安装器创建或重写环境文件时使用 0.0.0.0:<选择端口>。
  • 升级读取现有环境文件中的端口，无论旧地址是 127.0.0.1、Docker 网桥 IP 还是 0.0.0.0，都保留端口并把地址规范化为 0.0.0.0。
  • 用户仍可在环境文件中手工设置其他 Go net.Listen 可接受的地址；再次运行安装器时会按上述升级规则规范化。

改动范围

  • internal/config：默认值与回归测试。
  • scripts/install.sh：端口读取和环境文件生成。
  • scripts/lifecycle_test.sh：新安装、旧回环配置和自定义网桥配置测试。
  • packaging/sub2api-auto5h.env.example：发行示例。
  • README.md：Docker/Nginx 访问方式及公网暴露警告。

安全边界

0.0.0.0 会监听宿主机所有 IPv4 接口。如果云防火墙、安全组或本机防火墙允许所选端口，客户端可绕过 HTTPS 反向代理直接访问面板。部署者必须关闭公网端口，只允许 Docker/内网访问，或通过 HTTPS Nginx 统一入口访问。

  • 不自动修改 iptables、nftables、UFW、firewalld 或云厂商安全组。
  • 不改变登录、CSRF、SameSite、主密钥或 API Key 加密机制。
  • 启用 HTTPS 反向代理时仍需设置 SUB2API_AUTO5H_COOKIE_SECURE=true。

验收

  • 新安装默认环境文件包含 SUB2API_AUTO5H_LISTEN=0.0.0.0:2555。
  • 选择端口 3000 时生成 0.0.0.0:3000。
  • 旧配置 127.0.0.1:8090 升级后生成 0.0.0.0:8090。
  • 旧配置 172.19.0.1:4321 升级后生成 0.0.0.0:4321。
  • 生命周期 shell 测试、Go 测试、race、Vue、生产 Playwright 和双架构 Release 全部通过。
