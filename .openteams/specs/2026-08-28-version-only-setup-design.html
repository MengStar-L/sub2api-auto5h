初始化只验证管理连接

将 sub2api-auto5h 的首次初始化与 OpenAI OAuth 账号健康状态解耦，避免单个失效账号阻止管理员进入应用。

初始化唯一远端调用GET /api/v1/admin/system/version
成功条件Admin API Key 有效且版本满足最低要求
账号与额度初始化完成后在应用内处理

问题

当前初始化会先读取版本和全部 OpenAI OAuth 账号，再对第一个母账号调用 quota。只要该账号的 OpenAI OAuth Token 失效，即使 sub2api Admin API Key 完全有效，初始化也会被上游 401 阻断。

这混淆了两种不同状态：管理连接是否有效，以及某个远端账号是否健康。

目标与非目标

  • 初始化只验证 sub2api 管理连接、Admin API Key 和最低兼容版本。
  • 初始化期间不调用 accounts、quota、models 或 test 接口。
  • 账号同步和 quota 错误在应用内展示，不影响管理员完成初始化和登录。
  • 单个账号 quota 的 401、403 或 423 只暂停该账号，不触发全局暂停。
  • 账号列表等管理接口的 401、403 或 423 仍作为连接级故障，全局暂停调度。

本变更不放宽自动激活前的 quota 预检。任何账号在发送 hi 前仍必须通过原有 quota 结构和状态检查。

数据流

1. 初始化
验证 Setup Token、本地字段和管理员密码。
→
2. 连接验证
仅请求版本接口，验证 Admin API Key 与最低版本。
→
3. 进入应用
保存设置、完成初始化、唤醒调度器异步同步账号。

账号页首次打开时可能短暂为空；后台同步完成后账号出现。同步失败时由应用的全局状态和事件页展示连接错误。

错误归属

调用位置错误处理
初始化版本接口401/403、网络失败、版本过低或坏结构阻止初始化并在表单中显示错误
应用内账号列表同步401/403/423连接级故障，全局暂停并写入事件
应用内单账号 quota401/403/423 或 schema 错误保存到该账号的运行状态和 last_error，不暂停其他账号
单账号 quota429、5xx 或网络故障沿用额度重试策略

接口与实现边界

  • POST /api/setup/complete 成功响应只返回已验证的 version，不再返回带有误导性的 accounts_found。
  • 连接探测辅助函数只构建受限 sub2api 客户端并调用 Version。
  • 初始化成功后仍调用调度器 Wake，账号同步由既有后台流程完成。
  • 应用现有账号抽屉继续作为账号错误详情入口，不新增页面或数据库字段。
  • 手动刷新 quota 失败时也保存账号级错误，刷新页面后仍可查看。

测试与验收

  1. 假 sub2api 的版本接口返回成功，而 accounts 和 quota 被设置为失败；初始化仍成功，并断言失败接口调用次数为零。
  2. 版本接口使用错误 Admin API Key 返回 401；初始化必须失败且不保存设置。
  3. 版本低于兼容基线或响应结构错误；初始化必须失败。
  4. 应用内单账号 quota 返回 401；该账号显示“需要处理”及错误详情，调度器不进入全局暂停。
  5. 账号列表接口返回 401；调度器保持连接级全局暂停行为。
  6. GitHub Actions 完成 Go 单测/race、前端检查和生产面板 Playwright，再发布补丁版本。

文档调整

README 将明确：首次设置只验证管理连接与版本；账号列表和 quota 能力在进入应用后同步并按账号检查。兼容要求中的 quota 能力仍是自动激活的必要条件，但不再是完成初始化的前置条件。
